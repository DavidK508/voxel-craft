# История изменений сессии

## 1. Ошибка «A user gesture is required to request Pointer Lock»

**Файл:** `src/player/Input.js`

Было: `requestLock()` вызывал `canvas.requestPointerLock()` без проверки пользовательского жеста, что приводило к выбросу исключения `A user gesture is required to request Pointer Lock`, которое улетало в глобальный обработчик ошибок `main.js` и показывало экран «Не удалось запустить VoxelCraft».

**Исправлено:**
- Добавлен метод `hasUserActivation()` — проверяет `navigator.userActivation.isActive`. Если жеста нет, запрос пропускается.
- Добавлен метод `tryRequestLock(options)` — оборачивает вызов `requestPointerLock()` в try/catch и обрабатывает и синхронный выброс, и `.catch()` промиса. Никогда не выбрасывает за пределы класса.
- `requestLock()` теперь возвращает `boolean` (true — уже захвачено или успешно запрошено, false — жеста нет или запрос пропущен). Никогда не бросает исключение.

**Файл:** `src/game/Game.js`

- `requestLockWithHint()` обёрнут в `try/catch`. При неудаче через 900 мс показывается тост «Нажмите на мир, чтобы захватить мышь».
- `resume()` также использует `requestLockWithHint()` безопаснее.

## 5. Исправление двух багов рендера (сессия 3)

Пользователь сообщил: (1) боковые текстуры `snow_side`/`grass_side` перевёрнуты, (2) «где должна быть тень — светло, а где светло — тень».

### Баг 1. Перевёрнутые боковые текстуры

**Файл:** `src/world/mesher.js` → `meshChunk()`

**Причина (доказана):** мешер писал UV боковых граней как `v = worldY` (ось Y). Атлас — это `DataArrayTexture` с `flipY = false`, поэтому строка 0 текстуры — это **верх** канваса, а `t` растёт вниз. При `v = worldY` нижняя вершина грани брала верх тайла → бахрома (нарисованная маляром вверху канваса) оказывалась внизу грани. Верх/низ (`axis === 1`) были правильными, поэтому переворачивались только боковые грести.

**Исправление:** для осей 0 и 2 — `-p[1]` вместо `p[1]`:

```js
if (axis === 0) uvs.push([p[2], -p[1]]);
else if (axis === 1) uvs.push([p[0], p[2]]);   // верх/низ — без изменений
else uvs.push([p[0], -p[1]]);
```

При целочисленном `worldY` диапазон `[-Y-1, -Y]` покрывает ровно один тайл в обратном направлении — чистый вертикальный флип, горизонтальная ориентация не меняется. Пиксельных правок в `TextureAtlas.js` не потребовалось (маляры рисуют бахрому вверху канваса — верно).

### Баг 2. Инвертированное освещение

**Файлы:** `src/render/Sky.js`, `src/render/TerrainMaterials.js`

**Причина (доказана математически):** в `Sky.update()` стоял лишний `- Math.PI / 2` в формуле угла солнца:

```js
const angle = ((timeOfDay / 24000) * Math.PI * 2) - Math.PI / 2;
```

Часы (`formatClock`) идут по конвенции Minecraft: `t=0` → 06:00 (рассвет), `t=6000` → полдень, `t=12000` → 18:00. Без смещения `sin(angle)` даёт восход на `t=0` и зенит на `t=6000`; со смещением в **полдень солнце стояло у горизонта** (`sunY = 0`), отсюда ночное небо со звёздами и «плоский» свет при 12:00.

Второй фактор — перевес солнечной составляющей в шейдере (`faceShade * 0.62 + sun * 0.38`). При низком солнце на `t=6000` старый шейдер давал:

| грань | `faceShade*0.62 + sun*0.38` |
|---|---|
| верх (`sun=0`) | **0.620** |
| боковая +X (`sun=0.85`) | **0.774** ← ярче верха! |
| боковая +Z (`sun=0.54`) | 0.657 ← ярче верха! |

Т.е. боковые грести, освещённые низким солнцем, становились **ярче верхних** — ровно то, что видел пользователь.

**Исправление:**
1. `Sky.js`: `const angle = (timeOfDay / 24000) * Math.PI * 2;` (смещение убрано) — солнце в зените ровно на `t=6000`.
2. `TerrainMaterials.js`: веса `0.62/0.38` → `0.78/0.22` — MC-подобная константа грани (`faceShade`) остаётся основой, солнце даёт только направленную вариацию. Теперь на полдне: верх `1.0`, бок `0.569`, низ `0.343` — верх всегда самый светлый.

### Проверки (браузер, localStorage-фолбэк без Electron)

Собрана A/B-сцена: парящие блоки `snowy_grass`/`grass_block` и ступень с травой и снегом, камера на уровне центра блока (видна **только** боковая грань), `timeOfDay ≈ 5400–6000`. Старый код — вкладка `127.0.0.1:8765` (браузерный кэш отдавал прежние модули), новый — `127.0.0.1:8766` (другой origin → чистый кэш).

1. **Текстуры:** монтаж «до/после» — старый код: земля сверху, белая бахрома **внизу** с зубцами вверх; новый код: бахрома **сверху**, зубцы вниз. У травы — то же самое с зелёной бахромой.
2. **Небо/фаза солнца:** при `t≈5400–6000` старый код — ночь со звёздами и розовый горизонт; новый — голубое дневное небо с облаками.
3. **Яркость (одинаковая геометрия и камера):** верхняя грань земли 44.9 → 92.4 (×2.05), верхняя грань снега 89.9 → 178.0; отношение «верх/бок» у земли 1.44 → 1.79 (верх заметно светлее боковой).
4. **Тесты:** `npm test` → **14/14 проходит** (значения UV тестами не проверяются — только их количество).
## 6. Настоящие тени и ночь (сессия 4)

Пользователь: «где должна быть тень — наоборот светло», затем «ничего не изменилось», затем «сделай ночь темнее и чтобы тени двигались вместе с солнцем».

### 6.1. Тени от неба (вертикальный skylight)

**Файлы:** `src/world/mesher.js`, `src/world/World.js`, `src/workers/chunkWorker.js`, `src/render/TerrainMaterials.js`, `src/shared/blocks.js`

Раньше шейдер вообще не знал, закрыто ли небо над гранью: `faceShade` только делал верх светлее боков, поэтому теней от крыш/деревьев не было.

- В мешере добавлен `blocksSky()`: свет перекрывают `opaque`, `cutout` (листва) и `fluid`; блоки с `skyTransparent: true` (стекло) пропускают.
- `computeColumnTops()` считает верхнюю перекрывающую строку каждой колонки, `computeSky()`/`faceSky()` дают уровень 3 (открыто), 2 (свет заходит с края крыши/кроны) или 0 (закрыто).
- Уровень неба добавлен в ключ жадного мешера, поэтому квады не сливаются через границу тени.
- Новый атрибут `aSky` (Uint8, нормализованный) едет через воркер (`skies.buffer`) в `World.buildGeometry()` и умножает свет в шейдере: `sky = mix(0.35, 1.0, vSky)`.

**Заодно исправлен старый баг упаковки ключа:** `canMergeV` и `aoPack` читались из `key`, хотя в ключ заложен маркер `1 + body`. Из-за этого флаг слияния инвертировался, а один угол AO переворачивался (3 → 0), т.е. самый светлый угол рисовался самым тёмным. Теперь все поля читаются из `body = key - 1`.

### 6.2. Тени, которые двигаются вместе с солнцем

**Файлы:** `src/world/mesher.js`, `src/world/World.js`, `src/workers/chunkWorker.js`, `src/render/TerrainMaterials.js`, `src/shared/constants.js`, `src/render/Sky.js`

Солнце в игре всегда ходит в одной вертикальной плоскости: `sunX = cos(a)·0.55`, `sunZ = cos(a)·0.35`, `sunY = sin(a)` (константы `SUN_AXIS_X`/`SUN_AXIS_Z`). Значит, его горизонтальное направление — всегда либо `+axis`, либо `−axis`, и для честной тени достаточно двух горизонтов на грань: в сторону восхода и в сторону заката.

- Воркер генерации теперь возвращает `tops` — верхнюю перекрывающую строку каждой колонки чанка (`computeTops`).
- `World.buildHorizonMap()` сшивает `tops` соседних 3×3 чанков в карту 48×48 (радиус 16 блоков) и передаёт её мешеру.
- `horizonAt()` шагает по колонкам вдоль оси солнца и берёт максимальный `sin(угла)` до препятствия; `faceHorizon()` считает оба направления. Значения (6 бит на направление) входят в ключ мешера, поэтому тени не «размазываются» при слиянии квадов.
- В геометрию добавлен атрибут `aHorizon` (`vec2`, Uint8) и `horizons.buffer` в transfer list.
- Шейдер выбирает нужный горизонт по знаку `uSunDir.x + uSunDir.z` и считает `sunVis = smoothstep(horizon − 0.03, horizon + 0.03, uSunDir.y)`: пока солнце ниже препятствия — прямой свет не проходит. Тень удлиняется на рассвете, укорачивается в полдень и меняет сторону вечером.
- Прямой луч дополнительно гасится `vSky` (под крышей/кроной его нет совсем), а мягкий ambient-свет неба остаётся.

### 6.3. Ночь

**Файл:** `src/render/TerrainMaterials.js`

Было `daylight = mix(0.22, 1.0, uDaylight)`, причём солнечная составляющая не зависела от положения солнца — ночью земля светилась как днём.

Теперь общий множитель `day = mix(0.16, 1.0, uDaylight)`, а `sunVis` при солнце ниже горизонта равен нулю, поэтому ночью остаётся только приглушённый ambient. Открытая трава ночью стала примерно в 5–6 раз темнее днём (≈0.1–0.12 sRGB вместо ≈0.6), под кронами — почти чёрная.

### 6.4. Правки при изменении мира

`setBlock()` пересчитывает `tops` изменённого чанка и помечает грязными все 8 соседей: тень достигает 16 блоков и может менять освещение в любом из них. `applyEdits()` делает то же после применения сохранённых правок.

### Проверка

`npm test` → **15/15 тестов проходит** (включая тест «skylight puts the floor under a roof in shadow»). Визуальную проверку тени/ночи пользователь делает сам.

### 6.5. Исправление «кнопки в главном меню не работают»

Причиной был не UI, а синтаксическая ошибка в `src/render/TerrainMaterials.js`: в GLSL-комментарий попали обратные кавычки вокруг `vSky` **внутри** JS-шаблонной строки шейдера. Строка обрывалась, модуль игры падал на импорте, `Game` не создавался — обработчики кнопок не привязывались.

Исправлено удалением обратных кавычек из комментария. Проверено в браузере: ошибок в консоли нет, «Создать новый мир» открывает диалог, мир создаётся (52 чанка, 254 346 треугольников), атрибут `aHorizon` присутствует. Если игра уже запущена — её нужно перезапустить, старая версия модуля могла остаться в кэше.

- В диалоге нового мира появился выбор режима: **Выживание** / **Креатив**. Режим хранится в записи мира (`index.json`) и в самом сохранении (`gameMode`), поэтому список миров показывает «Выживание» или «Креатив», а загрузка возвращает нужные правила.
- Старые сохранения без `gameMode` считаются выживанием. Версия сохранения поднята до `SAVE_VERSION = 3`.
- **Креатив:** двойной `Space` включает/выключает полёт (`FLY_SPEED = 10.9`), урон и падение с высоты игнорируются, голод/кислород/лава не тратятся, блоки ломаются за 0.05 с, дроп и износ инструмента отключены, установка блоков и еда не расходуют предмет.
- Инвентарь креатива при старте заполнен девятью стаками строительных блоков (трава, земля, булыжник, доски, бревно, стекло, песок, кирпич, верстак). Клавиша `E` открывает не крафт, а каталог всех предметов реестра: ЛКМ выдаёт полный стак, ПКМ — один предмет.
- HUD и debug-панель показывают текущий режим, полёт и подсказки креатива.

### 7.2. Длительность дня и ночи

**Файлы:** `src/game/dayCycle.js`, `src/game/Game.js`, `index.html`

- В «Настройках» один ползунок «Длительность дня и ночи» от 1 до 60 минут. Он задаёт длительность каждой половины цикла, поэтому день и ночь всегда меняются синхронно и остаются равными. По умолчанию 10 + 10 минут — прежний полный цикл в 20 минут.
- День занимает тики `0..12000`, ночь — `12000..24000`. `advanceTimeOfDay()` получает одинаковые длительности из `cycleDurations()`, поэтому обе половины идут с одной скоростью.
- Настройки сохраняются в `localStorage` и в сохранении мира; старые сохранения с разными длительностями дня и ночи приводятся к одному значению. Текущее время и длительности видны в debug-панели.

### 7.3. Стартовый инвентарь

**Файлы:** `src/game/Inventory.js`, `src/game/Game.js`

- Новый мир в **выживании** начинается с полностью пустым инвентарём: предметы нужно добывать и крафтить. Загрузка сохранения восстанавливает инвентарь ровно в том виде, в каком он был сохранён.
- В **креативе** стартовая панель заполнена девятью стаками строительных блоков, а каталог по `E` даёт неограниченный доступ ко всем предметам. Расход предметов при установке и еде отключён, поэтому запас не заканчивается.
- Появились `Inventory.isEmpty()`, `Inventory.createCreative()` и `fillCreativeKit()`; стартовый набор выживания удалён.

### 7.5. Сессия 6: исправление порядка инструментов и сроков действия

**Файлы:** `src/game/Inventory.js`, `src/shared/items.js`, `src/ui/InventoryUI.js`

- Введено `withToolDurability()` — вспомогательная функция, которая гарантирует у каждого инструмента/орудия finite `durability`.
  - Деревянные кирки/мечи/топоры/лопаты быстро изнашиваются (durability = 60).
  - Каменные — дольше (durability = 132).
  - Железные — ещё дольше (durability = 250).
  - Алмазные — самые долговечные (durability = 1562).
  - Если при создании предмета durability не указана — функция подставляет максимальное значение из настроек инструмента.
- Исправлена нормализация durability при добавлении предметов в инвентарь (`add()`, `addStack()`, `setSlot()`) — все инструменты теперь имеют свойство `durability`, чтобы полоска прочности в UI работала корректно.
- Обновлён tooltip в инвентаре: при наведении на инструмент показывается «Инструмент · уровень N · скорость ×S» и «Прочность: X / Y».
- При крафте новой палки через `createItemStack()` durability автоматически нормализуется.

## 8. Дополнительные дома и защита посевов (сессия 6)

**Цель:** Увеличить количество домов в деревне и добавить механику охраны посевов домостроителями, аналогично тому, как железные големы охраняют поселенцев.

### 8.1. Увеличение количества домов

**Файл:** `src/world/generator.js` → `buildVillage()`

- Внедрена генерация **детерминистического кластера домов** вокруг центра деревни.
- Каждая entrada дома: `{ ox, oz, w, d, doorSide, style }`:
  - style 0 = стандартный (7×6)
  - style 1 = широкий (8×5)
  - style 2 = узкий (5×8)
  - style 3 = L-образный (объединяется в прямоугольник)
- Позиции вычисляются через `hash2i(vx, vz, seed ^ 0x9e8c, i)` для предсказуемости.
- Заменен жестко задаваемый список из 4 домов на динамическую генерацию 5 домов.

### 8.2. Домостроители-хранители посевов

  - Если моб ломает культур блок (64-67), фермент запоминает координаты.

  - При убийстве моба фермер собирает дропы культур (семена).
- Фермеры также защищают от монстров, wanderщих в огород: если моб заходит в зону фермы (определяется через `farm.minX/maxX, farm.minZ/maxZ`), фермер атакует.

## 10. Развитие до «полноценного Minecraft» (эта сессия)

### 10.1. Удаление Rust-порта

- Каталог `voxelcraft-rs/` полностью удалён. Основной проект — Electron-приложение в корне репозитория.

### 10.2. Вид от третьего лица

- `F5` переключает три режима камеры: 0 — от первого лица, 1 — сзади, 2 — спереди. Добавлены коллизия камеры и синхронизация модели с состоянием игрока.
- `Input` больше не перезагружает страницу по `F5`.

### 10.3. Броня

- 3 материала (кожа / железо / алмаз) × 4 слота, предметы ID 500–511, функции `getArmorInfo()` и рецепты шлема, нагрудника, поножей и ботинок.
- `Inventory`: массив `armor[4]`, `armorPoints()`, `damageArmor()`, `setArmorSlot()`, сериализация/десериализация и `clear()`.

- `src/world/Fluids.js` — клеточный автомат: вода 0–7, лава 0–3, источники, падающие колонки, высыхание без источника, взаимодействие лавы и воды → булыжник/обсидиан.

### 10.6. LAN-игра

- `src/main/lan.js` — TCP-сервер/клиент в main-процессе, обмен newline-delimited JSON через IPC/preload, до 8 клиентов.
- Хост авторитетен по сиду, правкам блоков и времени; клиент получает состояние мира и не пишет локальные сохранения.
- В меню кнопка «Играть по сети», экран с именем, портом и адресом сервера; статус подключения и список игроков.
- Удалённые игроки отображаются моделью `PlayerModel`; синхронизируются движение, правки блоков и время суток.
- Хост и клиент не паузятся автоматически при потере фокуса, иначе гости замирали бы.
